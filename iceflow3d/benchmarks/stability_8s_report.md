## 发现的问题与修复

### 1. 冰边界小截断距离使 HRR 应力发散

原来的虚拟速度是 `u_g = u_i + (u_wall-u_i)/eta`。当冰面贴近流体格点、
`eta≈0.05` 时，格点速度的微小误差被放大约 20 倍，再经过速度梯度、
非平衡应力和动量交换反馈到下一步。

300×100×60 的原实现第 2256 步（0.0282 s）在第一块冰附近失败；
失败场中的交替速度和小 `eta` 同时出现。这与全域 CFL 过大不同。

修复使用冰面和反方向流体点重建虚拟速度：

```text
u_g = [2 u_wall + (eta-1) u_(i-c)] / (1+eta)
```

它对线性速度场精确，系数有界；没有反向流体供体时采用有界反射。
回归测试覆盖 `eta=0.05,0.1,0.5,0.95`，并验证中心格点扰动不会被小间隙放大。
该修复消除了原来的早期失败，但单独应用仍在 0.068 s 的气液界面失败。

### 2. 二维 HRR 的高阶矩截断不能直接照搬到 D3Q27

二维无迹偏应力对唯一偶数四阶模态的贡献可以抵消；三维的三个偶数四阶
模态及混合四阶模态不具有同样的抵消。原实现只保留二阶偏应力，遗漏了
三维递推所需的四阶项，有限平移速度下会出现增长的格子模态。

修复内容：

- 使用 D3Q27 张量积平衡分布；以增量乘积计算，避免小速度下的相减损失。
- 从重建偏应力补齐 `220/202/022` 和 `211/121/112` 中心矩。
- 动态压力的原始 `222` 模态单独闭合，保持低阶矩和动量。
- 对 `c_a³=c_a` 导致的对角三阶平衡矩缺陷增加三次速度修正。
- 声学松弛率默认改为 0.6；剪切分子黏度和物理时间步保持原值。

均匀周期域的线性 Fourier 分析与 CUDA 小扰动实验相互验证：

| 碰撞版本 / 探针速度 | 预测每步模态幅值倍率 | CUDA 测量 |
| --- | --- | --- |
| 原 HRR / 0.1 LU | 1.001000515 | 1.000994458 |
| 递推矩与乘积平衡 / 0.1 LU | 0.999069663 | 0.999063072 |
| 加声学与三次项修正 / 0.2 LU | 0.998282538 | 0.998320530 |
| 最终源码、等价变换优化后 / 0.2 LU | 0.998282538 | 0.998260975 |

倍率大于 1 表示该模态增长。这些是指定均匀流动和指定波数的证据，
不是所有速度、波数、边界及密度比的无条件稳定性证明。
完整算例仍需要下面的密度源项修复；不能将失稳仅归因于声学率。

### 3. 密度梯度源项限幅改变了不可压缩方程

压力分布的零阶源项需要 `u·∇rho`。在对应的连续性关系中：

```text
div(rho*u) = u·grad(rho)  ⇒  div(u) = 0
```

旧限幅将右侧乘以 `alpha<1`，相当于引入：

```text
rho * div(u) = (alpha-1) * u·grad(rho)
```

这个人工体积源在低密度气相被放大；“限制源项幅度”反而成为晚期界面
失稳的主要触发因素。

同一 150×50×30 算例的对照：

| 改动 | 结果 |
| --- | --- |
| 保留两个旧限幅 | 第 4151 步，0.103775 s 失败 |
| 只关闭相场质量通量的动量限幅 | 第 4137 步，0.103425 s 失败 |
| 只关闭密度梯度源项限幅 | 完成 0.25 s |
| 同时关闭两个限幅 | 完成 0.5 s；后续运行到 3.7 s 无速度失稳 |
| 保留限幅但时间步减半 | 第 7228 步，0.09035 s 失败 |

默认 `density_gradient_source_limit=0`、
`phase_flux_acceleration_limit=0`，完整保留源项和相场质量通量。
后一个限幅不是该次失稳的主因，但单独改变动量中的质量通量会破坏两者的
输运一致性，因此一并关闭。旧选项保留用于复现实验。

质量与动量采用一致通量的理论背景可参见
[Zhan、Chai、Shi 的一致守恒相场 LBM](https://arxiv.org/abs/2111.00847)；
本次具体故障归因来自代码方程检查和上述开关对照实验。

### 4. 初始化和补点遗漏了零阶半步源项

旧初始化对运动分布减去半个密度源，却在静止分布加回相同总量，导致全部
分布的源项修正之和为零。含梯度时，变换后的分布应满足完整的 `-S/2`。

现在初始化和新流体点都使用完整半步源项。
碰撞回归同时检查零阶增量 `sum(f_post-f)=u·grad(rho)` 和一阶增量
`sum(c*(f_post-f))=F`，避免只检查动量而漏掉压力连续性错误。

### 5. 初始化覆盖了相场预热的结果

原 `_seed_populations` 调用同时初始化动量和相场的函数，使已经预热
2000 步的相场分布重新变成局部平衡，丢失预热建立的非平衡相场通量。

将“初始化动量”与“初始化动量及相场”分开。正常初始化仅设置动量；
新露出点仍同时重建两类分布。新增测试用零和非平衡扰动验证预热通量保留。

### 6. 移动/融化几何的局部补点产生额外水量

关闭失稳源项后，长跑揭示了第二类问题：3.7 s 时水体积增加 **3.2386%**。
即使融化核没有直接注水，冰占据格点变成流体后，局部外推仍可能填入水相；
这与本例“融化后消失、不生成液水”的模型不一致。

现在保存初始化后的封闭水量，在几何变化和补点后，将总量差异按
`phi*(1-phi)` 分配到弥散界面：

```text
phi_new = phi + lambda * phi*(1-phi),  -1 <= lambda <= 1
```

这个范围保持 `phi_new` 位于 `[0,1]`。对应分布以相同局部速度、动态压力
调整，保留原非平衡部分。累计体积调整、伴随的动量调整均写入诊断。
1 s 对照运行将体积误差降到约 `10^-9`；最终实现的验收容差依据 float32
精度设定，而非要求任意相场都能达到该对照运行的误差。

这是封闭水量约束的界面分配修正，不声称局部几何映射严格守恒动量或热量。
`phase_projection_momentum_*_n_s` 和 `thermal_remap_energy_j` 保留其影响。
库存约束按 `sum(phi)*dx³` 定义；原热场仍忽略 `phi<=10^-3` 的稀薄气侧
水量，因此相量与热场水体积的误差分别记录，不能混用两项指标。
界面加权体积分配的相关方法参见
[Huang、Lin、Ardekani 的体积分配研究](https://arxiv.org/abs/2010.01738)；
这里实现的是适合本例封闭双相库存的简化约束。

### 7. 均匀相场的单精度量化导致假失败

“整块冰突然消失”的测试使用均匀相场。所有格点会发生同方向舍入，因此
总量误差不随格点数量平均消失；原 `10^-9` 相对误差要求小于可表示精度，
导致修正迭代报不收敛。

容差改为 `max(10^-6 格点体积, eps_float32 * 初始相量)`，
仍保留有限迭代、无界面容量和真实不收敛检查。测试按相同精度核验总量，
而不是放宽速度或有限性检查。

### 8. 验证程序和测试隔离问题

- 源项测试会重写 `h`，最初没有恢复，可能污染后续耦合测试；已把 `h`
  加入保存和恢复列表。
- 周期平移诊断最初仅将迁移设为周期，力通量和三次修正仍使用容器边界；
  已统一为周期邻居。早期该探针的误差数据不能用于推断求解器精度。
- Taichi 延迟编译依赖源代码位置。长期运行采用冻结的源码副本和 SHA-256，
  避免修改正在运行的源文件而产生错误的 JIT 解析结果。
- 多个长期 CUDA 进程同时运行明显降低吞吐率；正式长跑顺序使用 GPU。

### 9. 原可视化快照无法精确续算

宏观场 NPZ 不含完整分布、待执行热更新、材料热状态和所有刚体状态。
新增原子写入的完整检查点：逐个数组写盘，避免瞬时复制多份大网格；
恢复时校验格式、字段和源码摘要。

测试逐数组比对恢复前后状态，再跨越热更新继续推进，验证冰融化和几何
变化能接续。诊断长跑交替保存两份检查点；失败步的宏观快照用于定位，
不能当作已经完成该步的重启状态。

### 10. 长时运行中不必要的计算开销

刚体接触先做世界坐标包围盒排除，再对可能接触的物体执行完整 15 轴 SAT；
远离的冰块不再构造九个叉积轴。

碰撞利用线性变换恒等式
`T^-1(T(base)+delta)=base+T^-1(delta)`，
避免每格每步重复变换已知平衡及源项分布。相场零阶仍单独精确闭合。
这些改动不改变物理参数和时间推进步数。

### 11. 诊断输出的浮点时刻累计误差

长跑中发现反复执行 `next_time += 0.1` 会把部分目标累积为
`1.6000000000000003`，导致 1.6 s 的帧延后一个诊断采样点。
诊断脚本已改为整数 LBM 步调度，并在输出目标处精确停止推进。
用采样步长 11、快照步长 3、检查点步长 5 的不整除组合验证，得到正确的
`0,3,6,…,21` 快照和 `15,20` 两份滚动检查点，最后仍在第 23 步结束。

粗网格前段沿用启动时的调度代码，每帧的真实步数、时间均
保存在 NPZ 中，不能按文件序号假设等间隔。这个问题不改变求解步数和结束
时刻；续算段使用修复后的调度，普通算例入口本来就使用整数步采样。

### 12. 最后一轮刚体接触修正后仍用旧残差判定失败

粗网格第一次长跑在尝试第 306058 步时退出，最后完整步为 306057，
即 7.651425 s。流体速度约 `7.38×10^-5` LU，并未失稳；错误来自
`contact projection did not converge`。

从 7.5 s 完整检查点重放，在第 308317 步再次捕获到同类故障，并保存了
接触求解前后的全部刚体状态。融化后质量集中、惯量缩小，剩余体素包围盒
仍较大；贴底的三个支撑点通过转动有效质量相互影响，逐点冲量需要较多轮
才能收敛。旧代码每轮记录的是**施加冲量前**的最大闭合速度，在最后一轮
结束后直接使用该旧值报错，没有检查已经修正的最终状态。

捕获状态中，32 轮后的实际穿透为 **0 格**，最大闭合速度为
**9.2501818×10^-8 LU**，已经满足原有 `10^-7` 容差。
现在只在迭代预算耗尽时，对所有墙面支撑点和物体间约束重新计算实际残差。
满足原容差则正常返回；真正不收敛仍报错，并附穿透和闭合速度数值。
没有增加迭代次数、改变冲量、冻结冰块或放宽容差。

修复后重放捕获的四块冰状态，全部位置、姿态、速度等数组与旧代码
32 轮后的结果逐元素完全相同，仅正确接受其已经收敛的状态。
小型状态夹具保存在 `tests/fixtures/late_floor_contact.json`。这项修复
解决的是错误判定，下一项处理真实残差尚未收敛的情况。

### 13. 融化残体的墙面逐点冲量收敛过慢

仅修复残差判定的 `run_source_v2` 又在第 311746 步、约 7.79 s 失败：
实际穿透为零，但实际闭合速度 `1.01463921×10^-7 LU` 仍超过原容差。
这次不是误报。原因是残体的实际惯量变小，而用于接触的剩余体素包围盒
支撑点间距仍较大，点冲量通过角速度强烈耦合，32 轮逐点投影不足以收敛。

在原迭代预算用尽、位置已满足约束而速度仍不满足时，增加同一墙面全部
支撑点的联合冲量求解。法向速度 Jacobian 的秩至多为三，枚举至多三个
独立活动约束的小型系统，要求冲量非负、全部接触点法向速度非负，
活动约束的法向速度为零。求解后重新核验所有墙面及物体间约束。
仍保留原 `10^-7` 容差、32 轮预算、无摩擦/无回弹模型及真实失败保护。

新增回归覆盖晚期捕获状态、低惯量慢收敛状态、不可容纳残体的真实穿透、
支撑点顺序无关及动能不增加；配置/刚体/输出模块合计 **16 项通过**。
另用固定随机种子的 500 组质量、惯量和速度组合检查非穿透速度及动能，
最大剩余闭合速度 `6.81×10^-16 LU`，动能增量上界为零。
结果分别在 `contact_fix_tests.log` 和 `contact_manifold_sweep.json`。

最终续算从 `final_150/checkpoint_0.npz` 的第 300000 步（7.5 s）出发，
使用冻结源码 `run_source_v3`，仅 `rigid.py` 与前段源码不同。
前段失败记录、失败场和冻结源码均保留。全程核验将前段至检查点的有效
数据与续算段连接，核对检查点哈希、配置、恢复首个采样的逐项一致性、
两段源码摘要，不把失败步的部分状态作为续算起点。

## 适用范围

额外的无重力、无表面张力周期平移诊断（密度比 800、给定速度 0.01 LU，
4000 步）保持有界，但并非精确保持匀速。修正诊断自身的周期边界后，
最终全域最大速度误差如下：

| 界面宽度 / 格 | 速度绝对误差 / LU | 相对给定速度 |
| --- | --- | --- |
| 5 | 0.00339714 | 33.97% |
| 10 | 0.00065515 | 6.55% |
| 20 | 0.00010148 | 1.01% |

加宽界面会明显减小该误差，说明高密度比下界面离散误差仍值得关注。
这里没有把加宽界面用作本例通过稳定性验收的手段：正式长跑保持默认 5 格。
这些结果是精度限制，不能被“稳定完成 8 s”掩盖，也不能直接当作固定物理
界面厚度的网格收敛证明。诊断保存在 `translation_corrected.json`、
`translation_w10.json`、`translation_w20.json`。

8 s 稳定性验证不替代网格收敛、时间步收敛或实验数据验证。冰接触仍为
剩余体素的有向包围盒近似，融化后凹形残体可能提前接触；没有断裂、再冻结
或亚网格润滑膜。封闭水量校正是非局部的数值修正，其动量和热影响已记录。
本次修复保持了原例“冰质量消失”的建模约定，没有将其改成真实融水注入模型。
