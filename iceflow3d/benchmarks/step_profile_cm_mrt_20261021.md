# CM-MRT 默认碰撞与 step profiling — 2026-10-21

[停用水量守恒修正的实验记录](phase_conservation_off_150_1s_20261021.md)。

默认动量碰撞已改为 **`cm_mrt`**。在 RTX 3090、450×150×90 网格的 0.1 s 检查点附近，本轮 CM-HRR 对照为 **59.058 ms/step**，CM-MRT 为 **55.587 ms/step**，耗时减少 **5.88%**，速度比 **1.062×**。动量碰撞核本身为 **6.020 → 2.560 ms**，耗时减少 **57.47%**；最大的剩余热点是全局水量投影。

## 修改内容

- `config.py` 的 `IceFlowConfig` 和四冰块算例的命令行默认值均为 `cm_mrt`；显式 `--momentum-collision-model cm_hrr` 仍可选择原模型。
- 数值测试的默认模型跟随改为 `cm_mrt`。HRR 专用 Fourier 模态诊断显式选择 `cm_hrr`，避免其理论与实际碰撞模型不一致。
- Blender 仿真入口增加同名碰撞选项；不指定时继承新默认，也能显式选择 HRR 以匹配历史检查点配置。
- profiling 入口支持显式模型选择及历史检查点源码变更选项，并记录检查点原模型、源码差异和实际运行配置。
- README 区分当前默认与既有 HRR 长时验收。完整检查点恢复仍沿用保存的模型，修改默认值不会自动转换已有检查点。

本轮没有修改碰撞公式、松弛率、黏度、时间步或稳定性阈值。求解器根目录源码摘要相比上一轮只有 `config.py` 改变；`simulator.py`、`thermal.py`、`lattice.py`、`rigid.py` 等核实现保持一致。

## 测量口径

- 硬件及环境：RTX 3090 24 GiB、i9-14900K、驱动 570.211.01；Python 3.13.9、Taichi 1.7.4、NumPy 1.26.4。
- 保留完整气水两相、四块冰、热对流、融化、刚体接触、水量约束及逐步稳定性检查。界面宽度为 5 格，热传导周期为 8 步。
- 新建算例先做 2000 步相场预热；各场景随后做 32 步耦合预热。再预执行整个测量窗口以完成条件路径的 JIT，恢复完整内存状态后计时。
- 每组 **3 次 × 128 步**。每次恢复全部设备字段、刚体数组及步数/热累计状态。初始化、预热、JIT、检查点读写、诊断及输出均不计入 step 时间。
- 吞吐使用未插桩墙钟中位数。独立进程测 CUDA event 时间；分层同步计时仅用于阶段归因。三者不能相加。同步插桩开销：小网格 9.83%，大网格初始 0.024%，大网格运动态 1.13%。
- 初始窗口为 step 32→160；0.1 s 窗口为 12032→12160，约 0.100267–0.101333 s。
- **0.1 s 检查点由 CM-HRR 演化得到。** 加载 step 12000 后，在首次碰撞编译之前选择待测模型，再按该模型预热 32 步。两种模型使用相同历史检查点和时间窗口，预热后物理场不保证相同；此结果是短时重启的完整 step 对比，不是 CM-MRT 从零推进到 0.1 s 的测量。
- 检查点与当前源码仅 `config.py` 的默认值不同，因此显式传入 `--allow-checkpoint-source-change`。原始检查点未修改，通用加载器的源码校验仍保持原样。

## 整体 step 结果

下表的 HRR 列来自[上一轮测量](step_profile_20261021.md)，保留它是为了与用户上次看到的基线直接比较。

| 场景 | CM-MRT 中位数 | CM-MRT 三次范围 | CM-MRT GPU 累计 | 上轮 CM-HRR | 相对上轮降时 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 初始，150×50×30 | **5.049 ms** | 5.029–5.080 ms | 3.649 ms | 5.167 ms | **2.28%** |
| 初始，450×150×90 | **43.160 ms** | 42.664–43.322 ms | 40.109 ms | 45.999 ms | **6.17%** |
| 0.1 s 检查点，450×150×90 | **55.587 ms** | 55.283–55.943 ms | 52.146 ms | 57.734 ms | **3.72%** |

另在本轮串行重测了运动态 CM-HRR 对照：**59.058 ms**，三次为 59.566、59.058、58.657 ms；独立 GPU 累计 **55.101 ms**。按这个本轮对照，CM-MRT 整体降时为 **5.88%**。本轮 HRR 墙钟比上一轮高约 2.3%，因此报告同时保留两套基线，不将它们混为同一测量。

GPU 同时承担桌面显示，未锁频；各组原始记录保存了测量结束时温度、频率和功耗。小网格的改进较小：水量统计、水热场记账、相场恢复仍占其 GPU 时间约 **54.3%**，分层计时中的刚体推进约 **0.936 ms/step**。

## 运动态 GPU 热点

以下 HRR 和 MRT 均为本轮独立 CUDA event 测量；MRT 占比的分母为 52.146 ms。

| 核/核组 | CM-HRR ms/step | CM-MRT ms/step | MRT GPU 占比 |
| --- | ---: | ---: | ---: |
| `_project_phase_volume` | 8.892 | **9.399** | **18.02%** |
| `_forces` | 6.000 | **6.046** | **11.59%** |
| `_stream` | 5.631 | **5.645** | **10.83%** |
| `_prepare_boundaries` | 5.035 | **5.035** | **9.66%** |
| `_gradients` | 4.303 | **4.245** | **8.14%** |
| `_measure_outflow` | 4.125 | **4.160** | **7.98%** |
| `_collide_momentum` | **6.020** | **2.560** | **4.91%** |
| `_measure_phase_balance` | 2.564 | 2.540 | 4.87% |
| `_collide_phase` | 2.341 | 2.358 | 4.52% |
| `_commit_water_targets` | 1.566 | 1.558 | 2.99% |
| `_recover_phase` | 1.404 | 1.377 | 2.64% |

碰撞核速度比 **2.352×**。CM-MRT 的静态分支跳过 HRR 的邻域速度梯度应力重建、递推高阶闭合、三次速度修正和独立压力模态闭合；这是碰撞算法选择带来的变化，不是保持原数值算法不变的等价优化。实现入口为 `simulator.py` 的 `_collide_momentum`。

水量投影与相量统计合计 **11.939 ms/step、22.89% GPU 时间**。两种模型的投影调用次数均为 **1.09375 次/step**，相量统计均为 **2.21875 次/step**；投影的实测耗时增加约 0.507 ms，抵消了部分碰撞收益。本次没有进一步隔离该差值的状态相关与硬件波动因素。

梯度仍调用 **3.125 次/step**，力计算 **2.125 次/step**。分层墙钟中普通几何刷新为 **18.141 ms/step**，热对流 **7.849 ms/step**，刚体推进 **0.974 ms/step**；这些阶段包含上表子核，不能重复累计。

## Nsight 交叉核验

额外捕获同一起点的 16 步 CM-MRT 窗口：墙钟 **55.420 ms/step**，GPU 核累计 **53.440 ms/step**，占约 **96.43%**。短窗口的投影频率与 128 步窗口稍有不同，数值不直接替代主表。

- 动量碰撞核为 **168 registers/thread**，上一轮 HRR 为 **213**；block size 均为 128。两者的 `localMemoryPerThread` 均为零，本次没有把速度变化归因于 register spilling。
- 16 步共有 **941 次 kernel launch**、**706 次 `cuStreamSynchronize`**。大量同步时间在等待 GPU 完成，不能直接视为同等大小的可删除 CPU 开销。
- 双向设备复制共 **605 次**，设备复制时间合计约 **0.472 ms/16 步**。复制带宽不是当前大网格主瓶颈。
- Nsight Systems 提供时间线及 launch 资源数据。硬件性能计数器仍受驱动权限限制，未测实际 occupancy、DRAM 带宽或 stall；不声称已证明具体某核达到带宽上限。

这些预算相互重叠，不能相加。现在即使把剩余动量碰撞耗时再减半，也仅节省约 **1.28 ms/step**，约为当前墙钟的 **2.3%**；因此下一轮不宜继续将碰撞核作为唯一优化重点。小网格则优先减少归约、同步和刚体状态上传的固定成本。

## 验证与边界

- CUDA 完整测试集 **29 项通过**，包含强迫动量增量、热输运守恒、融化补点、接触及完整检查点恢复；日志见 `outputs/profiling_20261021_cm_mrt/tests_cuda.log`。
- 已确认 Python 配置和普通命令行的默认模型均为 `cm_mrt`，显式 `cm_hrr` 仍可用。修改的 Python 文件通过 Ruff，辅助入口通过语法检查。
- 全部正式测量成功结束，保留逐步检查，末态数值诊断有限，气相修复次数和待补点数均为零。CM-MRT 测量末态相量相对漂移绝对值最大约 **1.72×10^-8**。
- 0.1 s 窗口末态最大 L1 速度：CM-MRT **0.118071 LU**，HRR 对照 **0.110145 LU**；模型切换确实改变了演化结果。
- **本轮只验证短窗口，未执行新的 5 s 或 8 s CM-MRT 长时验收。** 历史 HRR 验收不能用于证明新默认模型的长期稳定性。

## 复现

从仓库根目录执行，使用现有含 Taichi 的 Python。将 `wall` 替换为 `kernels` 可取得独立 GPU 计时；初始小网格将分辨率改为 150。

```bash
# 新建算例：省略模型参数即使用 cm_mrt
python iceflow3d/benchmarks/profile_step.py \
  --mode wall --resolution-x 450 --steps 128 --repeats 3 \
  --output iceflow3d/outputs/profiling_repeat_cm_mrt/early_450_wall.json

# 历史 HRR 检查点：显式选择新的碰撞模型
python iceflow3d/benchmarks/profile_step.py \
  --mode wall --steps 128 --repeats 3 \
  --checkpoint iceflow3d/outputs/dambreak_four_ice_blender_450_5s/stability_trials/original_0p1_checkpoint.npz \
  --momentum-collision-model cm_mrt --allow-checkpoint-source-change \
  --output iceflow3d/outputs/profiling_repeat_cm_mrt/active_450_wall.json

# 上一命令将模型改为 cm_hrr，并使用不同 output，即为本轮 HRR 对照
ICEFLOW3D_TEST_BACKEND=cuda python -m unittest discover -s iceflow3d/tests -v
```

原始 JSON、日志、Nsight 报告及图表位于 `outputs/profiling_20261021_cm_mrt/`；
