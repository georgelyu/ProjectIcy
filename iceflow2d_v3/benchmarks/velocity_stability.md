# 默认算例速度闪烁诊断与重构

本次以 `coupled_falling_ice_melting_2d` 的默认物理参数复现：100 × 200 网格，
90 °C 水，0 °C 冰，表面张力 0.072 N/m，LBM 时间步 6.25 μs。
改动前版本为 `2f728ea79f7b074ede0df3eec5d15e74e4ffb800`。

## 主要原因

旧的 `_refill_changed_nodes(melting=True)` 在冰体侵蚀后将露出的格点强制设为
`water_phase = 0`。水下因此产生了离散的空气孔洞；下一次碰撞计算会对这些新界面
施加表面张力，引起速度尖峰及向水体传播的压力扰动。示例的水/空气密度比为 800，
使这种突变尤其敏感。绘图使用固定速度色标，实际速度数组中也存在这些脉冲。

对照运行支持这个判断：将初始水温改为熔点后，没有融化和冷却浮力，脉冲显著减弱；
保留热融化但令表面张力为零，脉冲也显著减弱。只删除“侵蚀格点强制变空气”的分支，
其余算法和参数保持原样，已经消除了大部分快速波动。

## 定量结果

每 32 个 LBM 步采样一次，即采样间隔 0.0002 s。对当前液水格点（非墙、非冰，
`water_phase > 0.5`），计算相邻两次采样间**速度矢量差的空间 RMS**，
再统计 0.06–0.20 s 窗口内的均值和 95 分位数。不是平滑后的场，也不是守恒残差。
速度峰值取整个 0–0.20 s 窗口。

| 运行 | 速度变化 RMS 的均值，m/s | 95 分位数，m/s | 水中最大速度，m/s |
| --- | ---: | ---: | ---: |
| 改动前默认算例 | 0.010873 | 0.023559 | 0.582904 |
| 改动前代码，水温改为熔点 | 0.000164 | 0.000280 | 0.152738 |
| 改动前代码，关闭表面张力 | 0.000385 | 0.000584 | 0.190846 |
| 仅统一新露出格点的重建规则 | 0.000173 | 0.000283 | 0.152660 |
| 完成此次重构，默认物理参数 | 0.000142 | 0.000240 | 0.151937 |

最终速度变化指标较原版降低 **98.69%**。实际计算保留原来的黏性、碰撞松弛参数、
表面张力及时间步；没有对输出速度做平滑。
完整数值摘要见 [velocity_stability_results.json](velocity_stability_results.json)。

## 仿真逻辑调整

1. **冰的热状态只负责删除冰。** 吸热用于升温和侵蚀材料质量，不产生融水、融水显热
   或融水动量源项；没有全局质量或能量闭合检查。
2. **统一移动边界重建。** 运动或侵蚀都经 `_refresh_fluid_domain` 更新掩码、重建露出的
   相场、动态压力和速度。只读取本轮更新前后都属于流体的邻居，避免 GPU 读写竞态。
   必要时扩大搜索范围，处理一次露出多层格点的情况。水下延续周围水的状态，空气中
   延续空气状态；此局部外推不按融冰质量增加液体，也不保证全局水量不变。
3. **压力含义一致。** `pressure_lattice` 在冰格点和流体格点都保存总压力，外推时显式
   减去静水参考压力，避免掩码切换时混用总压力和动态压力。
4. **剩余材料统一决定几何。** 旧实现混用材料覆盖率和初始矩形距离；当格点恰好落在
   已经侵蚀掉的原始矩形边缘时，距离仍可能为零，残留假固体格点。现在固体掩码、
   接触范围和 cut-link 插值统一使用覆盖率构成的有符号水平集。该场用于求交，
   不宣称是严格的欧氏距离；小距离保护也随网格尺寸缩放。
5. **每个热子步完整提交侵蚀。** 依次更新质量/质心/惯量、几何、流体掩码和水温，
   然后才开始下一次导热，避免新覆盖率与旧掩码混用。一次露出多层水格点时，温度
   外推也搜索最近湿邻域，不再因超过三格而直接变成 0 °C。
6. 删除重复的初始宏观量恢复 kernel、初始矩形尺寸缓存、未使用的空气比热和导热率选项，
   以及为旧体积投影服务的“必须存在自由液面”限制。

`step` 仍清晰地按三个阶段推进：流体 → 刚体运动 → 热输运与侵蚀。

## 验证范围与运行方法

- `python -m pytest iceflow2d_v3 -q`：51 项通过。包括水下单格侵蚀无毛细冲击、空气中
  强制融化不产生液水、整块冰消失、多层温度外推、原始矩形边缘不残留固体及热子步同步。
- `python -m ruff check iceflow2d_v3` 和 `git diff --check` 通过。
- 默认参数连续运行 **4.0 s / 640000 步**，采样速度均有限，未触发稳定性异常。
  最终融化比例为 78.61%。完整自然融化到零不包含在这次 4 s 运行内，完全消失由上述
  独立回归测试覆盖。这些结果用于验证当前故障修复，不代表所有参数下的稳定性或网格收敛。
- 实际 example 运行 0.24 s，完成 25 帧速度、涡量、温度动画和 CSV/NPZ/metadata 输出。

从仓库根目录运行默认 example：

```bash
python -m iceflow2d_v3
```

重新测量速度稳定性（输出目录需不存在）：

```bash
python -m iceflow2d_v3.benchmarks.check_velocity_stability \
  --output-dir iceflow2d_v3/outputs/stability_check
```

可用 `--case cold_water`、`--case no_surface_tension`、`--case fixed_ice` 做对照，
`--end-time-s 4` 延长测量。诊断还报告前后两次都属于水的格点上的速度变化，
可用于排除显隐格点对统计的影响。

本次本机原始数据、比较图和动画保存在 `../outputs/stability_review/`。
其中 `baseline_source/` 留有改动前的 Python 源码和同一份诊断脚本；从该目录运行
诊断命令可以重跑改动前对照，不必修改当前工作区。
