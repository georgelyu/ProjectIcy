# IceFlow2D：下落冰块–热水–融化耦合

当前代码只保留一个仿真目标：
`examples/coupled_falling_ice_melting_2d.py`。冰块从空气区下落，穿过水气自由面，
在 `90 °C` 热水中继续平移、转动并融化。机械、热学和输出路径不再为非热冰块、
固定冰或独立 Stefan 基准保留分支。

## 运行

需要 NVIDIA CUDA GPU 和 Taichi：

```bash
python -m iceflow2d
```

等价的显式命令为：

```bash
python iceflow2d/examples/coupled_falling_ice_melting_2d.py
```

默认值如下：

| 参数 | 默认值 |
|---|---:|
| 物理区域 | `0.025 m × 0.050 m` |
| 网格 | `100 × 200` |
| 网格间距 | `2.5e-4 m` |
| 水深 | `0.030 m` |
| 方冰边长 | `0.008 m` |
| 初始转角 | `5°` |
| 最低冰角到水面的间隙 | `0.0015 m` |
| 水 / 冰 / 空气初温 | `90 / 0 / 20 °C` |
| 四面容器墙 / 水气及冰气界面 | 绝热 |
| 重力 | `9.8 m/s²`，竖直向下 |
| 参考速度映射 | `4 m/s ↔ 0.1 LU` |
| LBM 时间步 | `6.25e-6 s` |
| 慢热更新间隔 | `8` 个 LBM 步 |
| 仿真时长 / 采样间隔 | `3 / 0.01 s` |
| 采样数 | `301`（含初态） |

默认运行共 `480,000` 个 LBM 步。短测试可用：

```bash
python -m iceflow2d \
  --resolution-x 100 --resolution-y 200 \
  --end-time-s 0.00005 --output-interval-s 0.00005 \
  --no-plot --save-npz --no-progress
```

`--no-plot` 关闭终态图和三套 PNG/GIF；`--save-npz` 显式保留完整采样场；
`--no-progress` 关闭进度条；`--quiet` 同时关闭进度和摘要。完整参数见
`python -m iceflow2d --help`。

## 唯一保留的数值路径

流体使用两组 D2Q9 分布函数：压力–动量 LBM 演化动态压力和动量，守恒
Allen–Cahn 相场演化水体积分数。材料惯性密度由水相场插值得到，不把
`sum(f_q)` 当作跨越约 `800:1` 密度比的理想气体密度。

水池始终横跨活动域。`well_balanced_hydrostatics` 同时启用冻结参考密度、
静水压力分裂、残差重力和锐界静水压力牵引；这四部分是一套离散，不作为独立模式组合。

冰体只使用 `unified` cut-link 锐界。流体链路动量交换给出合力和力矩，刚体更新平移、
转动及墙面接触；不会额外叠加一个经验阿基米德力。冰体热状态保存在材料坐标网格，
因此刚体运动不反复插值固冰焓。世界网格保存液水体积和显热，并以当前位姿光栅化冰体覆盖率。

每个 LBM 步都执行位姿更新、流体开口重映射和水显热对流。导热、界面换热、潜热和
融水注入按 `thermal_update_interval` 多速率执行；默认每 8 步一次。融化后重新计算刚体
质量、质心和转动惯量，并把熔失的线动量与角动量守恒地转移给流体。

### 简单墙面约束

容器接触只采用整体几何约束。每次自由刚体更新后，根据当前融化冰块的 sharp support
把整体位置平移回物理墙以内；碰左/右墙时只截断穿墙方向的水平速度，碰下/上墙时只截断
穿墙方向的竖直速度。切向速度和角速度保持不变。模型不包含恢复、干摩擦、近壁薄膜力、
接触点冲量求解；墙面接触只是运动学的位置和速度约束。

## 水量与能量守恒

冰水真实密度分别为 `rho_i = 917 kg/m³` 与 `rho_w = 1000 kg/m³`。固冰体积减少
`ΔV_i` 时，生成的液水体积为：

```text
ΔV_w = (rho_i / rho_w) ΔV_i
```

剩余体积差由水气自由面吸收。相场投影只移动已分辨的弥散界面，保持纯水和纯空气为
严格不动点，并同步修正相场 populations 的平衡部分。若真实界面容量不足，代码会报错，
不会向整个水域或空气区添加均匀质量源。

热状态使用广延固冰质量、固冰显热、液水体积和液水显热。内部面热通量成对抵消；边界
热输入与总焓变化用于闭合能量残差。四面墙、水气界面和冰气界面均绝热；初始 `90 °C`
是水的初温，不是维持恒温的外部热库。机械能转热不在当前热模型中。

刚体移动或融化使流体节点启闭时，水体积与相场开口只做一次联合重映射。原先“覆盖率
搬运 + 全域供水池”会把冰旁的冷水分配到整条自由面，又把远处热水分配给新露出的冰旁
节点；全局守恒并不能阻止这种空间错误。现在已有液体保持其局部比显热，新露出的节点
从最近的湿邻域外推（最多三格），不从初始水温或空气温度补热。

重构后的显热用一次有上下界的全局校正保持总和：需要移除能量时按各格到最低温度的
热容量分配，需要补回时按到最高温度的热容量分配，因此不产生新的温度极值。此校正
是非局部的数值近似，不能当作高精度局部热通量。它避免每步求解几何输运方程，并删去
重复的覆盖率搬运；仍保留一阶迎风对流及每 8 步一次的导热更新，在成本和局部精度之间
折中。`aperture_energy_correction_abs_j_m` 记录累计校正绝对量，区别于守恒误差。

充分融化并混合后，可用下式独立核对最终温度（相对熔点 `T_m`）：

```text
T_eq = T_m + [m_w c_w (T_w0-T_m) + m_i c_i (T_i0-T_m) - m_i L]
               / [(m_w+m_i)c_w]
```

若分子为负，现有热量不足以完全融化，不能把负数当作全液态终温。默认网格扣除墙层后，
实际初始水面积为 `10998 dx² = 6.87375e-4 m²`，冰面积为 `6.4e-5 m²`。
因此完全融化增加 `5.8688e-5 m²` 的水（冰体积的 `91.7%`），平衡温度约 `76.64 °C`。
这里所有体积均按单位出平面厚度计算；刚体排水造成的暂时水面上升不等于生成融水。

## 耦合步顺序

一个完整步按以下依赖顺序执行：

1. 在旧位姿上完成动量/相场碰撞、流送、宏观量恢复和 cut-link 载荷归约。
2. 用当前动态质量性质积分刚体位姿，光栅化新覆盖率并重建启闭流体节点。
3. 根据新流体开口重构局部温度并闭合水量、显热总和；执行本步热对流。
4. 到达多速率热节点时，执行水/冰导热、成对界面换热、相变和融水注入。
5. 更新冰体质量矩、锐界和水量目标，再闭合熔失与流体获得的线/角动量。
6. 同步水相 aperture 和温度；输出归约只在快照前执行，新温度从下一次碰撞起反馈到浮力。

这个顺序保证流体、热场和刚体在采样时刻对应同一物理位姿。

## 输出

默认目录为 `outputs/iceflow2d/coupled_falling_ice_melting_2d/`：

- `history.csv`：每个采样时刻的一行标量诊断；
- `metadata.json`：请求参数、完整配置、格子尺度、输出清单和终态结果；
- `coupled_falling_ice_melting_2d.png`：终态温度/液相等摘要；
- `velocity_frames/` 与 `velocity_field.gif`；
- `vorticity_frames/` 与 `vorticity_field.gif`；
- `temperature_frames/` 与 `temperature_field.gif`；
- `fields.npz`：仅在 `--save-npz` 时生成。

PNG 与 GIF 逐帧写盘，不在内存中缓存整个序列。只有 `--save-npz` 会保留所有采样数组，
其内存量从 `O(Nx Ny)` 增为 `O(Nframes Nx Ny)`。

历史、NPZ 和 metadata 都保留关键验收量：活动水量目标/当前值/残差、热系统初始/当前
总质量与残差、总焓与边界热输入、ALE 水量/显热残差、相场 aperture 水量/能量残差与
容量、融水注入质量残差，以及冰体熔失和流体获得的线/角动量及其残差。
`water_mean_temperature_c` 是按实际液水质量加权的平均温度；metadata 中的
`closed_bath_reference` 给出完全融化水量和绝热平衡温度，便于独立核对。
兼容保留的 ALE 残差字段现在对应联合开口重映射。

## 模型边界

所有面积、质量、能量和惯量均按单位出平面厚度解释。当前只支持一个连通、保持刚性但
随融化侵蚀的冰体；融水不会重新附着或冻结回冰体。不包含断裂、多刚体、沸腾、蒸发、
汽化潜热、蒸汽输运或气泡。若剩余冰不再能视为一个连通刚体，模型假设即失效。
