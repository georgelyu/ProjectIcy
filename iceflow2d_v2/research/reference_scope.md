# iceflow2d 参考边界

数值实现只把指定场景参数和以下三类算法作为旧实现的参考。没有运行或导入 iceflow2d 包，也没有阅读其旧热求解、融水注入、补液、体积校正或刚体积分的函数体。曾读取函数名/位置清单以定位允许部分；名称清单不作为其他算法的实现依据。

## 场景参数

- examples/coupled_falling_ice_melting_2d.py：常量、build_parser、derive_geometry、create_config 中的几何、物性和边界配置。
- config.py：仅确认相关参数默认值和 ThermalBoundary / ThermalBoundarySet 的边界配置。
- simulator.py 的 _wall_at：确认容器四边都是闭合壁面。

场景配置中出现的旧热算法选择器、补液/投影参数不采用。几何尺寸和单位换算在本目录独立计算，结果见 scenario_reference.json 和 scale_analysis.json。

## 允许复用的算法内核

| 类别 | 读取范围 | 用途 |

| D2Q9 基本公式 | lattice.py:9–178 | 速度、权重、反方向、压力/相场平衡分布及矩重构 |
| 双相流碰撞 | simulator.py:3371–3698 | 压力型原点矩松弛、气液相场中心矩碰撞及其源项处理 |
| 双相流迁移与恢复 | simulator.py:3700–3815、3861–3897 | push streaming、宏观矩与压力恢复 |
| 碰撞所需相场邻居和力项接口 | simulator.py:2460–2480、3242–3368 | 仅相场导数、表面张力、碰撞黏性及力的矩结构；温度访问和新相变源独立重写 |
| SDF/材料坐标表示 | simulator.py:2483–2496、2509–2530、4587–4603 | 体坐标变换、指示量双线性采样和距离代理 |

行号用于本轮溯源；后续文件变化时应按函数名核对。

## 终端显示参考

2026-09-18 用户要求进度条与旧示例一致，额外仅查看旧示例的 `--progress` 参数及进度调用位置，以及 `reporting.py:1227–1311` 的 `_format_duration` / `_TerminalProgress` 显示辅助代码。v2 在 `examples/_progress.py` 中独立实现标准库进度条；数值算法参考范围仍按上表限定。

## 必须保留与必须新建的边界

1. 在 v2 内重新实现这些局部公式，不通过 import 旧 IceFlow2D 来间接带入其余算法。
2. 允许重排数据布局、融合重复读取、使用 f32 和分层归约，但无新源、几何不变时，允许复用内核应通过独立的一步公式对照。
3. 新的相变/气体体积源、守恒几何修正、能量转移和刚体积分位于明确的耦合接口；它们不是“把旧注水代码换一个名字”。
4. 旧代码内部的热字段访问仅作为依赖接口识别，不采用其温度计算、热量分配和融水注入实现。

## 查到的两个关键事实

- 压力分布的平衡零阶矩为 0，密度来自气液相场。因此不能用压力分布的零阶矩直接统计或添加融水质量。
- 旧 SDF 在材料网格内部使用“阈值减指示量”乘网格尺度的距离代理，只有外部矩形部分为标准距离形式。该量的差不能直接当成体积或严格的法向退缩距离。保留该查询和 cut-link 公式，同时新建几何积分与质量闭合。
